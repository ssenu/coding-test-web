# 배포 계획 (계획 3, 필수 범위)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 코딩테스트 웹을 컨테이너 1개로 묶어 `myserver`에 기존 앱들과 같은 방식으로 올리고, `https://cotest.ssenu.cloud`로 연다.

**Architecture:** 멀티 스테이지 Docker 빌드로 프런트엔드를 `dist/`로 만들고, FastAPI가 API·웹소켓과 정적 파일(SPA)을 함께 서비스한다. 서버에서는 저장소를 `/srv/apps/coding-test-web`에 clone해 `docker compose`로 빌드·실행하고, 서버 전용 `docker-compose.override.yml`로 `127.0.0.1:8009`에만 연다. Cloudflare Tunnel(`myserver`)이 `cotest.ssenu.cloud`를 이 포트로 넘긴다.

**Tech Stack:** Docker(node:24-bookworm-slim → python:3.12-slim), docker compose, uvicorn(`--proxy-headers`), Cloudflare Tunnel, GitHub Actions.

## 서버에서 확인한 기존 배포 방식 (2026-11-08)

| 항목 | 기존 앱들(codemarket, 4thIS-world 등) |
|---|---|
| 위치 | `/srv/apps/<저장소>` (GitHub에서 clone) |
| 실행 | 저장소의 `docker-compose.yml`로 `docker compose up -d --build`, `restart: unless-stopped` |
| 서버 전용 설정 | `docker-compose.override.yml`(git에 없음, 권한 600): `ports: !override ["127.0.0.1:<포트>:8080"]`, 프록시 헤더 설정 |
| 비밀값 | `.env`(권한 600), 저장소에는 `.env.example` |
| 외부 공개 | `~/.cloudflared/config-myserver.yml`의 `ingress`에 `hostname → http://localhost:<포트>` 추가, 수정 전 `.bak-<시각>` 백업, `systemctl --user restart cft-tunnel-myserver` |
| CI | `.github/workflows/ci.yml`: 테스트, 빌드, `docker build` |
| 사용 중인 포트 | 3000, 3100, 8001, 8003, 8005, 8006, 8007, 8008, 8081 → **8009** 사용 |

## Global Constraints

- 컨테이너 안 포트 8080, 데이터 볼륨 `/data`(SQLite, 첨부 파일), uvicorn 워커 1개.
- 서버 `.env`: `ADMIN_PASSWORD`(무작위), `SECRET_KEY`(무작위 64자), `COOKIE_SECURE=1`, `ALLOWED_ORIGINS=https://cotest.ssenu.cloud`.
- 공개 저장소에는 비밀값, 서버 전용 override, 주차장 문제 내용(시드 데이터)을 넣지 않는다. 시드는 로컬 폴더를 읽어 배포된 서버 API로 넣는 스크립트로 한다.
- Playwright 전체 흐름 테스트와 Alembic은 이번 범위에서 뺀다(첫 스키마 변경 때 Alembic 기준점을 잡는다).

## 작업

### Task 1: FastAPI가 프런트엔드 정적 파일을 서비스
- `backend/app/web.py`: `mount_web(app, dist)` — `/assets`는 StaticFiles, 그 밖의 GET은 실제 파일이 있으면 그 파일, 없으면 `index.html`(SPA). `/api`, `/ws`로 시작하면 404. `index.html`은 `Cache-Control: no-cache`.
- `Settings.web_dist`(환경변수 `WEB_DIST`, 없으면 서빙 안 함). `create_app` 맨 끝에서 마운트(라우터보다 뒤).
- 테스트 `tests/test_web.py`: 루트와 `/admin/runs/1`이 index.html, `/assets/x.js`, 없는 `/api/nope`은 404, 경로 탈출(`/../`) 차단, `WEB_DIST` 없으면 루트 404.

### Task 2: 보안 설정
- `backend/app/security.py`
  - 쓰기 요청(POST/PUT/PATCH/DELETE)과 웹소켓 연결의 `Origin`이 있으면 `ALLOWED_ORIGINS`에 있어야 한다(없으면 403 / 웹소켓은 연결 후 4403으로 닫음). `ALLOWED_ORIGINS`가 비어 있으면 검사하지 않는다(개발).
  - `Content-Length`가 12MB를 넘으면 413.
  - 응답 헤더: `Content-Security-Policy`(self, 인라인 스타일 허용 — Vue Flow·CodeMirror), `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, `X-Frame-Options: DENY`.
  - uvicorn 접속 로그와 웹소켓 로그에서 `token=`이 든 주소는 `?` 뒤를 지운다.
- `Settings.allowed_origins`(환경변수 `ALLOWED_ORIGINS`, 쉼표 구분).
- 테스트 `tests/test_security.py`.

### Task 3: Docker 이미지와 compose
- 루트 `Dockerfile`(web 빌드 스테이지 → python 런타임, 비루트 사용자, `/data` 볼륨, HEALTHCHECK `/api/health`, `uvicorn ... --proxy-headers --forwarded-allow-ips *`), `.dockerignore`, `docker-compose.yml`(`8080:8080`, `env_file: .env`, 볼륨, `restart: unless-stopped`), `.env.example`, `.gitignore`에 `.env`.
- 확인: 로컬 `docker compose up -d --build` → `/api/health`, `/`, `/admin` 응답.

### Task 4: CI와 실행 안내
- `.github/workflows/ci.yml`: backend(pytest), frontend(npm test, npm run build), docker build.
- 루트 `README.md`: 구조, 개발, 배포 절차(서버 override 예시, 터널 등록).

### Task 5: 주차장 시드 스크립트 (문제 내용은 저장소에 넣지 않음)
- `scripts/seed_parking.py --url <사이트> --password <관리자 비밀번호> --dir <student 폴더>`: 폴더의 `a_entry.py`~`e_main.py`를 시작 코드로, 박스 5개(공통 스토리, 개인 A~D, 팀 E, 결과)와 연결선(스토리→개인 자동, 개인→팀 승인, 팀→결과 자동)을 만들어 시험장으로 등록한다.

### Task 6: 서버 배포
1. `main`에 병합하고 GitHub에 푸시.
2. `myserver`: `/srv/apps/coding-test-web`에 clone, `.env`(권한 600), `docker-compose.override.yml`(권한 600, `127.0.0.1:8009:8080`) 작성, `docker compose up -d --build`, `curl 127.0.0.1:8009/api/health`.
3. `config-myserver.yml` 백업 후 `cotest.ssenu.cloud → http://localhost:8009`를 404 규칙 앞에 추가, `cloudflared tunnel route dns myserver cotest.ssenu.cloud`, `systemctl --user restart cft-tunnel-myserver`.
4. `https://cotest.ssenu.cloud/api/health`, 관리자 로그인, 웹소켓 연결 확인 후 시드 실행.
