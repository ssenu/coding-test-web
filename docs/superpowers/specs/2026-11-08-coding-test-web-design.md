# 코딩테스트 진행 웹 설계

- 작성일: 2026-11-08
- 상태: 설계 승인됨, 구현 계획 작성 전

## 1. 목적

여러 단계로 이뤄진 팀 코딩테스트를 진행하는 웹사이트를 만든다. 관리자는 시험의 흐름을 블록(박스)과 연결선으로 조립해 재사용할 수 있고, 진행 중에는 참가자들의 상태를 실시간으로 보며 단계를 넘긴다.

### 기준 진행 흐름

1. 공통문제 공개: 전체 아키텍처, 만들 결과물, 스토리 설명
2. 개인 코딩테스트: 참가자마다 파트 하나(a~f)를 풀고 코드를 제출
3. 관리자가 제출된 코드를 확인
4. 관리자가 승인하면 서로의 코드가 공유되고 팀 문제가 공개됨
5. 팀 코딩테스트: 회의하며 진행, 팀장이 앞 단계 코드까지 수정해 제출
6. 관리자가 최종 코드를 확인

첫 사용 사례는 주차장 관리 프로그램 과제다(개인 A~D: 입차, 출차, 요금, 현황 / 팀 E: 통합 + 정기권 추가 요구사항).

### 범위에서 제외

- 서버에서 참가자 코드 실행, 자동 채점
- 점수 부여, 코멘트
- 참가자 회원가입과 계정
- 여러 팀 동시 진행 화면 (데이터 구조는 회차 단위로 나뉘어 있어 나중에 확장 가능)
- 개인 단계 제출 이력 (마지막 제출본만 보관)

## 2. 확정된 결정

| 항목 | 결정 |
|---|---|
| 채점 | 없음. 관리자는 제출 코드를 읽기만 함 |
| 규모 | 한 회차에 참가자 최대 6명 (개인 박스 최대 6개) |
| 시험 구성 | 관리자가 캔버스에서 박스를 놓고 선으로 연결해 시험장(템플릿)을 만듦 |
| 연결선 | 선마다 "자동" 또는 "관리자 승인"을 선택 |
| 참가자 입장 | 입장 코드 + 이름. 관리자가 개인 박스 배정과 팀장 지정 |
| 팀 단계 편집 | 팀장만 편집·제출. 팀원은 실시간 읽기 전용 |
| 관리자 진행도 | 참가자 상태(입장 / 작성 중 / 제출)와 제출된 코드만 |
| 재제출 | 박스가 닫히기 전까지 가능, 마지막 제출본만 남음 |
| 진행 중 문제 수정 | 회차 안에서 박스 내용 수정 허용, 참가자 화면에 즉시 반영 |
| 공통 박스 완료 시점 | 열리는 즉시 완료 |
| 배포 | 인터넷 공개. 사용자의 홈서버, 보유 도메인, 도커 컨테이너 |
| 기술 | Vue 3 + Vue Flow + CodeMirror 6 / FastAPI + SQLModel + SQLite / 컨테이너 1개 |

## 3. 핵심 개념

- **시험장(템플릿)**: 박스와 연결선으로 짠 설계도. 여러 번 재사용한다.
- **회차(run)**: 시험장을 한 번 실제로 진행하는 단위. 회차를 열 때 시험장의 박스와 선을 통째로 복사(스냅샷)한다. 시험장 원본을 고쳐도 진행 중인 회차에는 영향이 없다.
- **참가자**: 회차에 속한다. 최대 6명.

### 박스 종류

| 종류 | 구성 요소 | 완료 조건 |
|---|---|---|
| 공통 | 문제 텍스트(마크다운), 첨부 파일 | 열리는 즉시 완료 |
| 개인 | 문제 텍스트, 첨부 파일, 코드 입력창(파일 이름, 시작 코드) | 배정된 참가자가 제출 |
| 팀 | 개인 박스 구성 + 앞 박스 제출 코드 자동 포함 | 팀장이 최종 제출 |
| 결과 | 없음. 최종 팀 버전을 모아 보여 줌 | 해당 없음 |

박스의 구성 요소(문제 텍스트, 첨부 파일, 코드 입력창)는 박스마다 켜고 끌 수 있다. 코드 입력창은 파일을 여러 개 둘 수 있다.

### 박스 열림 규칙

- 박스는 상태가 `잠김 → 열림 → 닫힘` 순서로만 바뀐다.
- 들어오는 선이 하나도 없는 박스(시작 박스)는 회차 시작과 동시에 열린다.
- 박스는 들어오는 선이 **모두** 충족되면 열린다.
  - 자동 선: 출발 박스가 완료되면 충족
  - 승인 선: 관리자가 승인하면 충족 (승인 버튼은 출발 박스가 열린 뒤부터 누를 수 있음. 출발 박스가 미완료여도 승인 가능하며, 이때 관리자 화면에 "미제출 n명" 확인을 띄움)
- 박스가 열리면 그 박스로 들어오는 선의 출발 박스는 모두 닫힌다. 닫힌 박스에는 제출할 수 없다.
- 팀 박스가 열리면 앞 개인 박스들의 마지막 제출본이 팀 파일로 복사된다. 같은 이름의 파일이 겹치면 팀 박스의 시작 코드가 아니라 제출본을 쓴다. 제출하지 않은 개인 박스는 그 박스의 시작 코드를 쓴다.
- 결과 박스는 들어오는 선이 충족되면 열리고, 그 시점에 회차가 "종료" 상태가 된다.
- 이 규칙은 `engine/flow.py`에 DB와 무관한 순수 함수로 둔다. 입력: 그래프(박스, 선), 박스 상태, 제출 여부, 승인 목록. 출력: 새로 열릴 박스와 닫힐 박스.

### 시험장 저장 시 검사

- 순환 연결이 없을 것
- 개인 박스 6개 이하
- 시작 박스(들어오는 선 없음)가 1개 이상, 결과 박스가 정확히 1개
- 모든 박스가 결과 박스까지 이어질 것 (끊긴 박스 없음)
- 공통·결과 박스로 들어오는 선은 자동/승인 모두 허용

## 4. 데이터 구조 (SQLite)

| 테이블 | 주요 컬럼 |
|---|---|
| `templates` | id, name, description, graph(JSON: boxes, edges), updated_at |
| `template_files` | id, template_id, box_id, filename, stored_path, size |
| `runs` | id, template_id, graph_snapshot(JSON), entry_code, status(`lobby`/`running`/`finished`), created_at, started_at, finished_at |
| `run_files` | id, run_id, box_id, filename, stored_path (회차 생성 시 template_files 복사) |
| `participants` | id, run_id, name, token_hash, assigned_box_id, is_leader, last_active_at, rejoin_requested |
| `box_states` | run_id, box_id, state(`locked`/`open`/`closed`), opened_at, closed_at |
| `edge_approvals` | run_id, edge_id, approved_at |
| `submissions` | run_id, box_id, participant_id, files(JSON: {파일명: 코드}), submitted_at (박스당 1행, 덮어씀) |
| `team_drafts` | run_id, box_id, files(JSON), updated_at (팀장 임시본, 덮어씀) |
| `team_versions` | id, run_id, box_id, version_no, files(JSON), saved_at, is_final |

- 박스 그래프의 각 박스: `id, type, title, position{x,y}, config{markdown, attachments_enabled, editor{files:[{name, starter}]}}`
- 각 선: `id, source, target, mode(auto/approval)`
- 접속 여부(온라인/오프라인)는 DB에 저장하지 않고 서버 메모리에서만 관리한다.

## 5. 화면

### 관리자

1. **로그인**: 비밀번호 하나. 환경변수 `ADMIN_PASSWORD`.
2. **시험장 목록**: 만들기, 복제, 삭제. 시험장별 지난 회차 목록과 "새 회차 열기".
3. **시험장 에디터**: 왼쪽 박스 팔레트, 가운데 Vue Flow 캔버스, 오른쪽 속성 패널(박스 내용 / 선 모드). 저장 시 3장의 검사 실행, 실패하면 문제 박스를 강조.
4. **회차 진행 화면**:
   - 상단: 입장 코드, 링크 복사, 회차 상태, 시작/종료 버튼
   - 왼쪽: 참가자 목록(접속 상태, 작성 중 여부, 파트 배정 드롭다운, 팀장 지정, 재입장 요청 승인)
   - 가운데: 읽기 전용 흐름도. 박스 색이 상태를 나타내고, 승인 선에 "승인하기" 버튼
   - 박스 클릭: 제출 코드 보기(파일 탭, 읽기 전용), 문제 텍스트 수정
5. **결과 보기**: 최종 팀 코드와 버전 목록. 버전을 누르면 그 시점의 파일을 본다.

### 참가자

1. **입장**: 입장 코드 + 이름 → 대기실("관리자가 파트를 배정하고 있습니다").
2. **작업 화면**: 왼쪽에 내가 볼 수 있는 박스 목록(완료 / 진행 중 / 잠김), 오른쪽에 문제와 첨부 파일, 아래에 코드 입력창과 제출 버튼, 마지막 제출 시각.
   - 개인 단계: 열린 공통 박스와 **내 개인 박스만** 보인다.
   - 팀 단계: 팀장은 모든 파일 탭을 편집하고 "저장"(버전 생성)과 "최종 제출"을 한다. 팀원은 같은 화면을 읽기 전용으로 보며 팀장의 편집이 실시간 반영된다.
3. **종료**: 최종 코드를 읽기 전용으로 보여 준다.

## 6. 실시간 처리

- 클라이언트마다 웹소켓 하나: `/ws/runs/{run_id}`. 관리자는 세션 쿠키, 참가자는 토큰으로 인증.
- 상태 변경(제출, 승인, 저장, 배정, 문제 수정)은 REST API로 처리한다. 서버는 DB 커밋 후 웹소켓으로 이벤트를 보낸다.
- 서버 → 클라이언트 이벤트: `participant_updated`, `box_state_changed`, `submission_received`(관리자만), `box_content_updated`, `team_draft`(팀원에게), `run_status_changed`, `rejoin_requested`(관리자만).
- 클라이언트 → 서버 웹소켓 메시지: `typing`(입력 신호, 5초 간격으로 묶어 보냄), `team_draft`(팀장만, 0.5초 디바운스).
- 재접속 시 `GET /api/runs/{id}/state`로 전체 상태를 다시 받은 뒤 이벤트를 적용한다. 재접속은 지수 백오프로 자동 시도.
- "작성 중": 최근 60초 안에 `typing` 신호가 있으면 표시.
- 팀장 임시본은 팀원에게 중계하면서 `team_drafts`에도 덮어쓴다. 개인 단계의 작성 중 코드는 브라우저 localStorage에만 저장한다.
- uvicorn 워커는 1개로 고정한다(웹소켓 연결 정보를 메모리에 둠).

## 7. 오류 상황

| 상황 | 처리 |
|---|---|
| 새로고침, 창 닫기 | localStorage 토큰으로 같은 자리에 자동 재입장 |
| 다른 기기에서 같은 이름으로 입장 | 관리자에게 재입장 요청 표시. 승인하면 새 토큰 발급, 이전 토큰 무효 |
| 닫힌 박스에 제출 | 409 응답, "이 단계는 닫혔습니다" 표시. 작성한 코드는 화면에 유지 |
| 팀장 접속 끊김 | 관리자가 진행 중에도 팀장 변경 가능. 임시본은 서버에 있음 |
| 승인 중복 클릭 | 같은 결과(멱등). 이미 승인된 선은 무시 |
| 서버 재시작 | 상태는 SQLite에 있음. 접속 정보만 사라지고 클라이언트가 자동 재접속 |
| 입력 크기 | 코드 파일 하나 200KB, 첨부 파일 하나 10MB 초과 시 거절 |
| 6명 초과 입장 | 대기실 입장은 허용하되 배정 가능한 개인 박스가 없으면 관리자 화면에 경고 |

## 8. 보안

- 관리자: 서명된 HttpOnly 쿠키 세션 (`SECRET_KEY`).
- 참가자: 무작위 토큰(32바이트), DB에는 해시만 저장.
- 입장 코드: 6자리 영숫자. IP별 시도 횟수 제한.
- 참가자에게 보낼 박스와 코드는 서버에서 권한에 따라 걸러서 보낸다.
- 제출 코드는 실행하지 않고 텍스트로만 저장·표시한다. 마크다운은 DOMPurify로 정리 후 렌더링한다.

## 9. 테스트

- `engine/flow.py` 순수 함수: pytest로 집중 테스트. 주차장 시나리오(공통 → 개인 A~D 자동 → 팀 E 승인 → 결과)와 경계 사례(미제출 승인, 다중 입력 선, 시작 박스 여러 개).
- API와 웹소켓: FastAPI TestClient로 제출, 승인, 권한 거절, 닫힌 박스 제출 거절, 재입장.
- 프런트엔드: Vitest로 시험장 저장 전 검사 규칙.
- 전체 흐름: Playwright 1개 시나리오. 관리자가 시험장 생성 → 회차 열기 → 참가자 4명(브라우저 컨텍스트 4개) 입장·배정·제출 → 승인 → 팀장 수정·최종 제출 → 결과 확인.
- 시작용 데이터: 주차장 과제 시험장을 시드 스크립트로 넣는다. 공개 저장소에는 문제와 시작 코드만 두고 정답 코드는 넣지 않는다.

## 10. 배포

- 멀티 스테이지 Dockerfile: Node로 Vue 빌드 → Python slim 이미지에 FastAPI와 정적 파일 → `uvicorn app.main:app --workers 1`.
- 볼륨 `/data`: `app.db`(SQLite), `files/`(첨부 파일). 백업은 이 폴더.
- 환경변수: `ADMIN_PASSWORD`, `SECRET_KEY`, `DATA_DIR`(기본 `/data`).
- `docker-compose.yml` 예시 제공.
- 리버스 프록시는 웹소켓 업그레이드 헤더(`Upgrade`, `Connection`)를 넘기도록 설정. HTTPS는 프록시가 처리.
- DB 마이그레이션: Alembic.
